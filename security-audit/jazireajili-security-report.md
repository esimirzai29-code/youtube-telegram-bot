### ۲. ایندکس `wp-json` باز است و لیست افزونه‌ها را لو می‌دهد — شدت: 🟡 کم

**آدرس:** `https://jazireajili.ir/wp-json/`
**مشکل:** هر بازدیدکننده‌ای می‌تواند لیست کامل افزونه‌ها را ببیند (Elementor/Pro، RankMath، Contact Form 7، پیامک ووکامرس، YITH Wishlist، Jetpack...). خودِ این موضوع آسیب‌پذیری نیست، ولی «اثر انگشت» سایت را برای مهاجم آسان می‌کند.

**راه‌حل:** افزونه **Disable REST API** یا کد زیر در قالب (فقط برای کاربران لاگین‌نکرده ببند — چون ووکامرس و اپلیکیشن ممکن است به REST نیاز داشته باشند، با احتیاط):
```php
// functions.php قالب فرزند
add_filter('rest_authentication_errors', function ($result) {
  if (!empty($result)) return $result;
  if (!is_user_logged_in()) {
    // اجازه دسترسی به روت‌های فروشگاه برای مهمان، بستن بقیه
    $route = $GLOBALS['wp']->query_vars['rest_route'] ?? '';
    if (strpos($route, '/wc/store') !== 0 && strpos($route, '/wc/v') !== 0) {
      return new WP_Error('rest_forbidden', 'دسترسی محدود است', ['status' => 403]);
    }
  }
  return $result;
});
```
> ⚠️ قبل از اعمال، در محیط تست امتحان کن چون ممکن است درگاه پرداخت یا افزونه پیامک به REST نیاز داشته باشد.

**راه‌حل — آپدیت امن قدم‌به‌قدم (حتماً به همین ترتیب):**

2. بررسی کن **افزونه درگاه پرداخت** با ووکامرس جدید سازگار است (صفحه افزونه درگاه را بخوان).

4. بعد **ووکامرس** را آپدیت کن و آپدیت دیتابیس را اجرا کن (ووکامرس → وضعیت → ابزارها).

6. **تست کامل:** صفحه محصول، افزودن به سبد، تسویه حساب تا مرحله پرداخت، فرم تماس و پیامک.
7. اگر مشکلی بود، از بکاپ برگرد و در محیط تست (Staging) اول امتحان کن.

> 💡 اگر لایسنس المنتور پرو فعال نیست و آپدیت نمی‌شود، اول لایسنس را تمدید کن — نسخه نال‌شده/قدیمی پرو یکی از شایع‌ترین راه‌های هک است.

**جلوگیری از لو رفتن نسخه در آینده** — بلاک کردن فایل‌های readme در `.htaccess`:
```apache
<FilesMatch "^(readme|license|changelog)\.(html|txt|md)$">
  Require all denied
</FilesMatch>
```
(این جلوی آپدیت را نمی‌گیرد؛ فقط خواندن عمومی را بلاک می‌کند.)

#### ⚠️ نکته مهم: `?author=1` از داخل ایران باز است!
از خارج کشور WAF آن را بلاک می‌کند (403) ولی اسکن داخلی **HTTP 200** گرفت —
یعنی مهاجم با IP ایران می‌تواند نام کاربری را حدس بزند. WAF جایگزین دفاع عمقی نیست؛
با یکی از این دو روش مستقل از WAF ببند:

```apache
# روش ۱: htaccess — بلاک شمارش نویسنده
RewriteEngine On
RewriteCond %{QUERY_STRING} ^author=([0-9]*)
RewriteRule .* - [F]
```
```php
// روش ۲: functions.php قالب فرزند
add_action('template_redirect', function () {
  if (is_author()) { wp_die('دسترسی مجاز نیست', 403); }
});
```

#### ⚠️ هدرهای امنیتی (تأیید از داخل: هیچ‌کدام فعال نیست)
WAF هاست هدر اضافه نمی‌کند؛ در `.htaccess` فعال کن (قطعه کد در چک‌لیست، بخش 🟡).

| ثبت‌نام مشتری ووکامرس | 🟡 باز است (نقش customer — برای فروشگاه لازم است) |
| فرم آپلود فایل | ✅ در صفحات اصلی پیدا نشد |
| `?author=1` | 🔴 نام کاربری لو رفت: **admin** |
| لیستینگ uploads | ✅ بسته (403) |

**زنجیره‌های حمله (به ترتیب واقعیت):**

1. 🔴 **Brute-force روی `admin` — تهدید شماره ۱ و واقعی.** نام کاربری ادمین لو رفته + صفحه ورود از داخل ایران باز است (WAF فقط خارجی‌ها را بلاک می‌کند). مهاجم فقط باید رمز را حدس بزند. **اقدام امروز:** ساخت ادمین جدید با نام یکتا → انتقال مطالب → حذف `admin` + فعال‌سازی 2FA + محدودسازی تلاش ورود.
2. 🟡 **رنک‌مث:** نسخه 1.0.272 از باگ سطح مشترک (‏CVE-2026-34892‏، تا 1.0.271) **در امان است** ✅؛ فقط CVE-2026-77786 (نیازمند نقش Editor) شاملش می‌شود که با ثبت‌نام عادی (subscriber/customer) قابل رسیدن نیست. اقدام: آپدیت به 1.0.277 + چک کردن نبود Editor ناآشنا.
3. 🟡 **المنتور XSS:** نیازمند حساب ویرایشگر+ است. اقدام: در **تنظیمات → عمومی** مطمئن شو «نقش پیش‌فرض کاربر جدید» روی **مشترک** است + ثبت‌نام عمومی وردپرس را ببند (تیک «هرکسی می‌تواند ثبت‌نام کند» را بردار — ثبت‌نام مشتری ووکامرس از تنظیمات خودش کار می‌کند و مختل نمی‌شود).
4. 🟢 **نقص آپلود پرو (‏CVSS 9.8‏):** اسکن v1.1 روی **۳۱ صفحه (کل سایت‌مپ)** هیچ فرم آپلودی پیدا نکرد → سطح حمله عملاً بسته است. آپدیت پرو همچنان واجب است ولی فوریت بحرانی ندارد.
